# PAX 연결

연결 코드는 더 이상 없습니다. 스크립트가 이 PC 에 대기 프로세스를 띄우고 브라우저를 열며, 사용자가 브라우저에서 PAX 에 로그인해 프로젝트를 고르고 [연결]을 누르면 연결됩니다(신원 증명 = PAX 로그인, 코드는 같은 PC 로만 이동). 사용자가 코드를 붙여넣어도 **무시**하세요. GitHub CLI 는 연결에 필요 없고, clone/push 단계(`pax-local-setup`)에서만 필요합니다.

## 1. 연결 스크립트 실행 (인자 없이)
```bash
node "${CLAUDE_PLUGIN_ROOT:-$PLUGIN_ROOT}/bin/vibeagent-connect.mjs"
```
- Codex 에서 두 환경변수가 모두 없으면 **이 SKILL.md 가 있는 폴더 기준 `../../bin/vibeagent-connect.mjs`** 경로를 쓰세요.
- 이 스크립트는 **기다리지 않고 바로 끝납니다**(대기 프로세스 기동 + 브라우저 열기 + 주소·확인값 출력). 출력을 **먼저 사용자에게 전달**한 뒤에 기다리세요.
- 출력 **`브라우저에서 연결을 진행하세요: <주소>`** → 사용자에게 "브라우저에서 프로젝트를 고르고 [연결]을 눌러 주세요. 브라우저가 안 열렸으면 주소를 `#` 뒤까지 복사해 **이 PC** 의 브라우저에서 여세요" 라고 한 줄만. 주소를 대신 열거나 요약하지 마세요. **`확인값 …`** 줄은 그대로 함께 전달(브라우저 화면과 같아야 이 PC 의 연결).
- 첫 줄 **`이전 연결 시도가 실패했어요(…)`** → 그 문장을 전달하고 계속(새 대기는 이미 시작됨).
- 출력 **`진행 중인 연결 대기에 이어 붙었어요`** → 이전 대기가 아직 살아 있는 것. 인자 없는 실행이면 스크립트가 같은 연결 주소를 브라우저에 다시 엽니다(`--wait` 폴링은 열지 않음). 그 문장과 주소·확인값을 그대로 전달하세요(새로 시작하길 원하면 `--restart`).
- 그다음 같은 스크립트를 **`--wait 30`** 으로 실행해 30초씩 확인하세요. 마지막 줄이 **`waiting:`** 이면 다시 실행(최대 20회 ≈ 대기 수명 10분) — 재실행은 진행 중인 대기에 **이어 붙을 뿐** 새 탭을 열지 않습니다. 그래도 `waiting` 이면 "브라우저에서 [연결]을 누른 뒤 다시 요청해 주세요" 로 멈추세요.
- **종료 4**(`listener_failed`) → 로그 경로를 알리고, 샌드박스가 의심되면 터미널 직접 실행을 안내.
- **`연결 실패 —`** → 문장을 그대로 전달(코드는 1회용 — 재실행이 유일한 재시도).
- **`PAX 연결 완료:`** → 다시 묻지 말고 "연결됐어요. 이어서 이 프로젝트의 로컬 개발 환경을 준비할게요." 한 줄 뒤 **`pax-local-setup`** 으로 clone → 환경변수 → 개발 서버 실행까지 자동 수행. 출력에 **`folder_mismatch: repo=<주소> suggest="<경로>"`** 줄이 있으면(지금 폴더 ≠ 고른 프로젝트) 이 폴더에서는 진행하지 말고, "지금 폴더는 P1 이에요. 방금 고른 P2 를 `<경로>` 에 내려받아 준비할까요?" 를 한 번만 묻습니다. 예 → `git clone <주소> "<경로>"`(경로는 따옴표째; `exists=1` 이면 생략) → `vibeagent-sync-skills.mjs --project-dir "<경로>"` → "그 폴더를 열고 새 대화에서 '준비해줘'" 안내. 아니오 → "P2 는 P2 폴더에서, 이 폴더의 P1 은 다시 연결" 만 안내하고 멈춤.
- 이어서 진행하려면 `pable-pax-preview` MCP 도구가 **실제로 로드돼 있어야** 합니다. 도구가 목록에 안 보이면(특히 **Codex 첫 설치**) 아래 2번을 먼저 수행하세요.

## 2. (Codex) MCP 도구가 안 보이면 — 재시작 → 예비 절차
플러그인 설치만으로 `pable-pax-preview` MCP 서버가 뜹니다. 도구가 목록에 없으면 먼저 **Codex 를 완전히 재시작**(앱 종료 후 재실행 — 새 대화만으로는 부족)한 뒤 다시 확인하세요.

- 예전에 `~/.codex/config.toml` 에 직접 적어 등록한 블록(`[mcp_servers.…]` 중 `vibeagent-mcp-proxy.mjs` 경로를 가리키는 것 — 구 이름 `[mcp_servers.vibeagent]` 포함)이 있으면 **삭제**하세요. 그 경로에는 설치 당시 버전 번호가 박혀 있어, 플러그인을 업데이트해도 옛 프록시가 함께 로드돼 도구가 중복으로 보이거나 옛 버전으로 동작합니다.
- 재시작 후에도 도구가 없을 때만(예비 절차) `node "<플러그인 루트>/bin/vibeagent-connect.mjs" --print-proxy-path` 가 출력한 경로로 아래 블록을 추가하고 다시 재시작하세요. 이 블록은 다음 플러그인 업데이트 뒤 다시 지워야 합니다.

```toml
[mcp_servers.pable-pax-preview]
command = "node"
args = ["<절대경로>"]
```

- Codex 는 MCP 서버를 **시작 시점에만 로드**합니다. 위 추가만으로는 **현재 세션에 도구가 뜨지 않으며, 에이전트는 Codex 를 직접 재시작할 수 없습니다.** 사용자에게 **"Codex 를 완전히 재시작(앱 종료 후 재실행)한 다음 '이어서 진행해줘'라고 말씀해 주세요"** 라고 요청하고 거기서 멈추세요.
- ⚠️ manifest·env 값을 가져올 **다른 로컬 명령이나 우회 경로를 찾지 마세요.** 그 값은 오직 `pable-pax-preview` MCP 도구로만 제공됩니다.
- Codex 는 **한 번에 한 프로젝트**만 연결됩니다(플러그인 폴더에서 실행되므로 최근 연결이 쓰임). 다른 프로젝트로 바꾸려면 그 폴더를 Codex 에서 열고 다시 연결하세요. `get_project_manifest` 의 `repoUrl` 이 작업 폴더의 remote 와 다르면 그 사실을 사용자에게 알리고 진행을 멈추세요.

## 3. 연결 끊기
사용자가 "연결 끊어줘" 를 요청하면 `disconnect` 도구를 호출한 뒤 `/pax-preview:disconnect` 명령의 절차대로 토큰 파일을 지우세요(Claude 에선 `/pax-preview:disconnect`).
